## 5. 합성 정지 라벨 규칙 (`dyn_relabel.py`)

### 5.1 정의와 수치

| 항목 | 정의 | 수치 |
|---|---|---|
| 대상 물체 | person과 other(자전거·스쿠터·유모차 등)의 이동체 | 끼어든 차와 차량형 소품(car)은 뺀다. MORAI는 대회에서 정적 에셋이 움직이지 않는다고 답했다 |
| 서 있는 물체 | 출발 전 물체와, 경로 끝에 멈춘 소품은 피할 대상이라 이 풀에서 뺀다 | 사람은 차로에 들어와 서 있어도 대상이다(enter_stop: 기다림) |
| 보임 | 물체가 움직이는 중이고, 카메라 위치(base_link + 1.4 m)에서 거리 ≤ 50 m, 진행 방향 대비 각도 ≤ 100°(전방 + 좌우 카메라), 주차차(ra_parked, 4.6 × 1.9 m)에 가려지지 않음 | 가림 판정은 `label_check.visible`이다(LiDAR 위치에서 물체 중심·모서리로 쏜 2D 광선이 차량 상자를 지나는지). 한 번 보이면 계속 보인 것으로 친다 |
| 충돌 경로 | 물체를 t0 속도(경로 프레임 vs, vl)로 6.4 s(0.1 s 간격) 예측해, 다음을 모두 만족하는 시점이 있다: \|lat − 자차 계획 횡위치\| ≤ 0.95 + 0.5 + 0.35 = 1.8 m, 코 앞 간격 > −0.5 m이면서 < 50 m, 예측 시각 ≤ 자차 뒤끝이 그 지점을 지나는 시각 + 1 s | 자차 계획 횡위치는 원래 주행 미래 경로의 d를 s로 보간한 값이다. 지나는 시각은 현재 속도(최소 0.5 m/s) 기준이다 |
| 정지 목표 | 코에서 물체 가까운 끝까지 거리 D에서 정지 여유 3 m를 뺀 곳 | D는 예측이 아니라 복원 궤적(실제 미래)의 물체 위치로 단계마다 계산한다. 물체가 그 뒤 경로 폭에 있을 동안은 남은 최솟값을 유지한다(접미 최솟값) |
| 필요 감속 | a_need = v0² / 2(D − 3). D − 3 ≤ 0.05 m면 무한대 | – |
| 부드러운 정지 (soft) | a_need ≤ 2.5 m/s²: 원래 주행을 유지하다가, 감속 A = max(SOFT_A, a_need)의 정지 포락선 √(2A·남은 거리)에 닿는 곳부터 선다 | SOFT_A = 2.0 m/s² (제안) |
| 급정거 (hard) | a_need > 2.5 m/s²: 그 프레임부터 A = min(a_need, a_max)로 제동한다. a_max로도 못 서면 a_max를 유지한다 | 45행이 a_need > a_max다 |
| 원래 주행과의 관계 | 라벨 = min(원래 속도, 포락선). 원래 드라이버가 더 일찍·세게 서면 그대로 둔다 | 포락선에 묶인 단계의 감속은 a_max 이내다 |
| 정지 유지 | 제동이 시작되면 물체가 경로 폭에 있는 동안 속도를 다시 올리지 않는다(기어가기 없음). 0 아래로도 내려가지 않는다(GT 정지 잡음 −0.03 m/s를 따라 뒤로 가지 않음) | – |
| **재출발 (마스크 대신, 사용자 10/28)** | 물체가 경로 폭을 벗어난 단계부터 0.5 s 동안 속도를 유지하고, 그 뒤 1.5 m/s²로 가속한다. 원래 속도를 넘지 않으며, 따라잡으면 원래 주행으로 돌아간다 | 정지 행 6,184개에 재출발이 들어 있다. 벗어나는 시점 중앙값: soft 2.1 s, hard 3.5 s, hold 1.7 s, popout_soft 2.4 s. 근거: 물체가 떠나는 것은 카메라·LiDAR로 보이므로 예측할 수 있는 출발이다. 0.5 s는 사람 반응 시간 정도다. 1.5 m/s²는 R2 드라이버의 실제 재출발보다 완만하다(R2 A 정지 후 0.5 → 5 m/s 198건, 평균 가속 p25 1.87 / 중앙값 3.25 m/s²). 원래 속도를 상한으로 두어, 원래가 다른 이유로 낮을 때는 그대로 따른다 |
| 경로 | 위치는 원래 경로 그대로다. heading은 라벨 이동 거리로 원래 yaw를 보간한다 | 미래 = `ego_trajectory`와 같은 적분(0.1 s, 64점) |
| 반대 예시 (pass) | 보이는 이동체가 코 앞 0–50 m에 있지만 충돌 경로가 아니거나, 충돌 경로였어도 제때 비켜 라벨이 원래와 같다. 원래 주행은 브레이크를 밟지 않는다: v0 ≥ 2 m/s, 미래 최저 ≥ max(v0 − 1.5, 0.6 v0) | 라벨 = 원래 주행. 예: 길 따라 걷기, 자차가 지난 뒤 건너기, 건너기를 마친 사람 옆에서 다시 가속. 가상 에피소드 없이 원래 에피소드 행을 쓴다 |
| 행 범위 | R2 A 395개 에피소드의 index 행, i ≥ 15, 미래 64행이 있는 행 | index 밖 행(충돌 등으로 traj_ok가 꺼진 행)은 로더가 쓸 수 없어 못 넣었다 |

## 7. 전처리 방식: 행 단위 가상 에피소드 (로더 코드 그대로)

| 항목 | 내용 |
|---|---|
| 왜 | 사용자 10/28 "그냥 전처리 해서 데이터셋 넘기면 되는거 아니야?" 로더·손실 코드(`data.py`, `finetune.py`, `student.py`)는 정지 보강 run도 쓰므로 바꾸지 않는다 |
| 가상 에피소드 | 합성 정지 행마다 `<원래 에피소드>_dyn<i:05d>` 하나다(6,566개). 행마다 미래가 달라서 행 단위다 |
| ego 표 | `_dyn_relabel/ego/<가상>.npz` = 원래 `_ego/<ep>.npz` 전체에서 v·yaw의 i+1 … i+64만 합성 미래로 바꾼 것이다(압축 npz, 합 120 MB). 이력(i−15 … i)과 다른 필드는 그대로다 |
| index | `_dyn_relabel/dyn_index.parquet`: 원래 행의 열(tau, cell, split, nav_text, fog, hour, scene) + episode = 가상 이름, `src_episode`, `kind`. dyn 소스는 `index: _dyn_relabel/dyn_index.parquet`로 읽는다 |
| 센서 | 가상 폴더의 `cams.bin`, `cams_index.npz`, `lidar.bin`, `lidar_index.npz`, `meta.json`은 원래 에피소드를 가리키는 상대 링크다 |
| 상자에서 | B2는 링크를 저장하지 않는다. step0_r2와 `_dyn_relabel/`을 받은 뒤 `python scripts/dyn_stage.py $R2_ROOT`를 한 번 돌린다. `<가상>/`에 센서 링크를, `_ego/<가상>.npz`에 ego 링크를 만든다(다시 돌려도 안전). 이어서 `python scripts/dyn_load_check.py $R2_ROOT`(CPU)로 확인한다 |
