# 근거리 돌출(pop-out) 데이터 검수 (2026-10-29)

읽기·분석만 했다. 학습 코드·설정은 고치지 않았고, GPU 상자는 쓰지 않았다. 숫자는 모두 B2 사본을 Mac에서 직접 계산한 값이다. 추정이면 "추정"이라고 적었다.

## 0. 판정 요약

- **"보이면 선다"를 이 데이터 그대로 가르치기는 어렵다.** 배울 수 있는 부분은 반대쪽 갓길(far) 사건이다. 정지 행의 59.5 %(4,592행, 280사건)를 차지한다. 이 사건들은 20–24 m에서 보이고, 라벨 시작 행의 필요 감속 중앙값이 2.1 m/s²라 실제로 설 수 있다. 다만 라벨이 끝까지 서는 비율은 2.9–16 %다. 대부분 "줄였다가 다시 가는" 라벨이다.
- 목표였던 근거리 돌출(가림 + 가까운 갓길)은 396사건, 3,125행이다. 이 부분은 라벨 그대로는 배울 수 없다.
  - 라벨 시작 행에서 이미 52.5 %가 a_max(6.96 m/s²)로도 못 선다.
  - 행 단위로 보면 82.8 %(가림)·76.1 %(가까운 갓길)가 a_max를 넘는다.
  - 가림 행의 53.4 %는 라벨 궤적 자체가 이동체와 겹친다.
  - 가림 사건의 85.1 %는 라벨이 Front 카메라에 ≥30 px로 보이기 전에 시작한다. 시작 행의 4프레임 중 이동체가 보이는 프레임은 평균 0.61장이다.
- **모든 행에 걸친 입력 결함이 하나 있다.** 학습 행의 81.6 %가 nav_text로 `"Follow the road"`(속도 제한 문구 없음)를 쓴다. 인덱스가 없는 에피소드에 들어간 대체값이다. 이 문자열은 R1 인덱스(2,086,127행)와 R2 인덱스(121,523행)에 한 번도 없다. `build_index.nav_text`는 항상 속도 문구를 붙이므로, 같은 규칙을 쓰는 평가 입력에도 나오지 않을 것이다(배포 쪽 코드는 직접 보지 않음). 모델이 이 문구를 "정지 라벨"의 단서로 외울 수 있다. dynbal이 쓴 병합에 가장 가까운 06:09 병합에서는 69.4 %였다.
- **행동 공간이 라벨 끝을 못 담는다.** 이산 토큰의 감속 상한은 6.78 m/s²로, 라벨 상한 6.96보다 낮다. 정지 행의 58.0 %에서 가속 토큰이 잘리고, 36.9 %에서는 토큰 복원 궤적이 라벨보다 1 m 넘게 더 간다.
- **재출발 행(2,398행)은 입력끼리 서로 맞지 않는다.**
  - 100 %가 실제로는 10.5 m/s(중앙값)로 달리는 카메라 프레임인데, 이력만 정지(0)로 바꿨다.
  - 74.2 %는 정지 행과 프레임이 완전히 같고 라벨만 다르다.
  - 출발 시점 자체는 맞다. 충돌 전 Object Info로 확인할 수 있는 914행에서 회랑 안 출발은 0이다.
- **이력은 좋다.** 돌출 정지 행의 이력은 실제·합성 모두 감속 단서가 0.2 %다. 그러나 함께 섞는 R2 동적 정지 행(동적 정지의 30 %)은 실제 75.3 %, "속도 보존" 합성도 72.6 %가 감속 단서를 담는다.
- **"동적 정지에 가중치를 더 주면 정지를 배우나?"** 지금 데이터로는 아니라고 본다(추정, 폐루프 미검증).
  - 가중치를 올리면 함께 커지는 것이 있다. nav_text 단서(81.6 %), 물리적으로 불가능한 목표(53.1 %), 이동체와 겹치는 목표(28.7 %), 토큰 경계에 붙은 목표(58 %)다.
  - 따로, 입력·물리 조건(Front에 안 보임, a_max 초과, 라벨 겹침, 이동 0.3 s 미만) 중 하나라도 걸린 정지 행을 빼면 2,437행·353사건(정지 행의 31.6 %)이 남는다. 그 91 %가 far다. 근거는 6절과 11절에 있다.
- dynbal이 "여전히 박는다"의 원인이 이것이라고 확인하지는 못했다. 위 결함과 맞아떨어진다는 것까지가 추정이다.

## 4. 물리적 가능성

필요 감속은 a_need = v² / 2(거리 − 3 m)이다. 라벨 규칙과 같다.

| 구간 / 시작 | 시작 행 a_need 중앙 | 시작 행에서 이미 a_need > a_max | 정지 행 a_need > a_max | 라벨 궤적이 이동체와 겹침 | 원래 주행이 겹침 | 라벨이 6.4 s 안에 완전 정지 |
|---|---|---|---|---|---|---|
| 동적 · 반대쪽 | 1.10 | 0 % | 28.5 % | 14.5 % | 87.1 % | 16.3 % |
| 동적 · 가까운 | 4.74 | 44.4 % | 74.0 % | 50.5 % | 82.3 % | 67.7 % |
| 동적 · 가림 | 6.86 | 49.8 % | 82.3 % | 52.3 % | 91.9 % | 21.3 % |
| 터널 · 반대쪽 | 2.13 | 0 % | 33.7 % | 11.7 % | 59.0 % | 2.9 % |
| 터널 · 가까운 | 9.17 | 87.5 % | 90.0 % | 46.7 % | 83.3 % | 0 % |
| 터널 · 가림 | 7.76 | 55.3 % | 83.8 % | 55.0 % | 91.3 % | 18.4 % |
| **전체** | 4.63 | **30.8 %** (208/676) | **53.1 %** | **28.7 %** | 73.6 % | 11.8 % |

- 피할 수 없는 사건: 라벨 첫 행에서 이미 a_max를 넘는 사건이 30.8 %다. 가림·가까운 갓길만 보면 52.5 %(396 중 208)이고, 반대쪽은 0 %다.
- "겹침"은 계획 경로의 이동체가 회랑(±1.8 m) 안에 있는 동안 자차 차체([−0.8, +3.9] m)와 s 구간이 겹치는 것이다.
- 라벨 감속(정지 행 최대값): p10 2.34, p25 4.32, 중앙 6.96 m/s²다. 61.3 %가 상한 6.96에 붙어 있다. 완전 정지 라벨(911행)의 평균 감속은 중앙 6.63 m/s²다.
- 정지 행 a_need 분포: 중앙 7.77, p75 24.3, p90 99 이상이다. 거리 3 m 이하는 99로 잘라 셌다.
- 원래 주행의 결말: 사건의 63.2 %가 충돌로 끝났다.
- 설계 쪽 원인(계산값): 10 m/s에서 a_max 6.96으로 서려면 7.2 m + 정지 간격 3 m가 필요하다. 가림·가까운 갓길의 시작 행 거리는 중앙 8.8–11.3 m다. 발동 12–20 m에 보행자 10–15 km/h이면, 자차가 RDDF 속도로 달릴 때 대부분 경계선 위다.

## 5. 학생 행동 공간이 라벨을 담는가

- 행동 공간은 unicycle (가속도 a, 곡률 κ)다. 정규화는 a_n = (a − 0.029) / 0.681이다.
  - flow matching 목표는 자르지 않는다.
  - 이산 토큰(traj_ce 손실, 이력 토큰)은 a_n을 [−10, 10]으로 자른다. 그래서 담을 수 있는 감속은 **6.78 m/s²**이고, 라벨 상한 6.96보다 낮다.
- 결과:

| | 정지 행 | 재출발 행 |
|---|---|---|
| 가속 토큰이 하나라도 잘린 행 | **58.0 %** (가림 88.8–89.5 %, 반대쪽 35.3–37.4 %) | 0 % |

### 6.2 입력과 라벨의 불일치
- 드라이버가 서지 않았으므로, 제동 시작 뒤 모든 행의 카메라·LiDAR·이력은 계속 순항하며 다가가는 장면이다. 각 행의 입력끼리는 서로 맞는다. 라벨은 그 행에서 새로 시작하는 정지다.
- 문제는 나머지 30.6 % 행이다. 모델이 시작 행에서 제동했다면 결코 오지 않는 상태(정책 밖 상태)이고, 68.2 %가 물리적으로 불가능하다. 이 행들은 "이미 늦은 상태에서 a_max로 밟되 그래도 부딪히는" 목표를 가르친다.

### 6.3 nav_text 대체값 (입력 결함)
- `popout_relabel.py`는 인덱스가 없는 에피소드에 `cell="C?"`, `nav_text="Follow the road"`를 넣는다(base 대체값).
- `_popout_index`가 264에피소드뿐이라 **학습 행의 81.6 %**가 이 값이다. 정지 80.3 %, 재출발 85.6 %다. 06:09 병합에서는 69.4 %였다.
- 같은 자리의 실제 문구는 다르다.
  - 동적 구간: `Go straight through the intersection in Xm. Speed limit 60 km/h`
  - 터널: `Follow the road. Speed limit 60 km/h`
- `"Follow the road"`와 정확히 같은 문자열은 R1 인덱스 2,086,127행, R2 인덱스 121,523행에서 **0번** 나온다. 학습 전체에서 이 문구가 돌출 정지·재출발 라벨에만 붙는다는 뜻이다. 평가 입력에도 나오지 않을 것이다(추정, 0절).

## 7. 이력

이력 1.5 s의 Δv = v(t0) − v(t0−1.5)다. 감속 단서 = Δv < −1 m/s 또는 이력 중 가속도 < −2 m/s².

| 데이터 | 이력 | 행 | Δv 중앙 | 감속 단서 비율 | t0 속도 중앙 |
|---|---|---|---|---|---|
| 돌출 정지 | 실제 | 7,717 | **+2.63** (가속 중) | 0.25 % | 9.8 |
| 돌출 정지 | 합성(속도 보존) | 7,717 | +2.45 | 0.21 % | 9.7 |
| R2 동적 정지 | 실제 | 7,579 | −1.46 | **75.3 %** | 6.0 |
| R2 동적 정지 | 합성(속도 보존) | 7,579 | −1.32 | **72.6 %** | 6.0 |

- 돌출 정지 행은 이력이 순항이라, 정지는 시각만으로 배워야 한다(의도대로). 합성 이력은 7,717행 모두에 있다.
- 다만 이력이 Δv +2.6 m/s로 "가속 중"이다. 에피소드가 정지 상태에서 30–50 m 앞에 띄워 시작하기 때문이다. 평가에서 순항으로 들어오는 경우와 분포가 다르다.
- R2 동적 정지(동적 정지 17 % 중 30 %)는 실제 이력도, "속도 보존" 합성 이력도 감속을 그대로 담는다. 합성은 경로 모양만 바꾸고 속도 프로필은 유지한다. 그래서 real 50 / synth 50 섞기로는 이 단서가 지워지지 않는다. 칸별로는 A_soft 87 %, A_popout 74 %, A_hard 69 %, B_soft 77 %다.

### 11.2 "가중치를 더 주는 것"이 의미가 있으려면 먼저 고칠 것
1. **nav_text를 실제 값으로 바꾼다.** 732에피소드 모두에 `build_index`를 돌리거나, 가상 행에 `build_index.nav_text(path_s)`를 넣는다. 기계적인 수정이고 다시 녹화할 필요가 없다. 이것을 고치지 않고 가중치를 올리면 문구 단서만 강해질 가능성이 크다(추정).
2. **물리적으로 불가능한 목표를 뺀다.** a_need > a_max 행과 라벨이 겹치는 행이다. 둘 다 빼면 정지 행 3,620행·466사건이 남는다(84.8 %가 반대쪽). 위 2,437행은 시각 조건까지 뺀 값이다. "피할 수 없을 때 최대 제동"을 따로 가르치려면 별도 소스로 두고 가중치를 올리지 않는다.
3. **라벨 시작을 입력에 맞춘다.**
   - 시작 행 = Front에 ≥30 px로 보이고, 이동이 0.3 s 이상 지난 첫 행이다.
   - 그 전 행은 뺀다(원래 라벨도 없음). 지금 규칙(2D 모서리 + 이동 0.05 s)은 카메라보다 이르거나 단서가 2 px 미만이다.
4. **라벨 상한을 토큰 범위 안으로 둔다.** a_max ≤ 6.78이다. 그러지 않으면 traj_ce가 더 가는 궤적을 가르친다. 레시피 변경이라 사용자가 정할 일이다.
5. **재출발 행은 빼거나 실제로 선 프레임으로 만든다.** 지금 프레임은 10 m/s 주행 중이다.
6. **R2 30 % 쪽 이력 단서.** 합성 이력이 감속을 보존하므로 동적 정지 가중치를 올리면 이 단서도 같이 커진다. 합성 이력의 속도를 t0 속도로 평평하게 하는 등의 수정이 필요하다(제안).
7. **녹화 분포.** 가까운 갓길이 4 %뿐이다. 가림 이동체 생성 실패(733건)도 고쳐야 한다. 다시 녹화할 때는 RDDF 속도에서도 설 수 있는 발동 거리를 쓴다. 10 m/s라면 이동체가 회랑에 들어올 때 코까지 거리가 v²/2a + 3 m = 10.2 m 이상이어야 한다(반응 지연 0 기준 계산값). 평가 v2와 비슷하게 순항 진입, 중앙선 너머 출발도 넣는다.

1–3을 고친 뒤 남는 행(2,437–3,620행, 85–91 %가 반대쪽)에 가중치를 올리는 것이 "보이면 선다"를 직접 강화하는 길이다. 근거리 돌출을 정말 배우게 하려면 7번(녹화 조건)이 필요하다.
